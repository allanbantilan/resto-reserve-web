Restaurant Reservations
Setup guide

A restaurant website with an editable menu and table reservations. The local stack includes WordPress, MariaDB, and Mailpit for captured test email.

Local result: the site was installed from a fresh Docker volume and the reservation flow passed in Chrome and the API smoke test. The existing site is available at http://127.0.0.1:18087/.

1. Requirements

  • Docker Desktop with Docker Compose.
  • PowerShell 7 or newer for setup.ps1.
  • Node.js for the reservation smoke test; Python and Chrome for the optional Chrome MCP check.
  • Free local ports 18087 and 18088, or two other free ports.

2. First local installation

Open PowerShell in the project directory. Check ports, set a unique admin password for this shell session, then run setup:

Get-NetTCPConnection -LocalPort 18087,18088 -State Listen -ErrorAction SilentlyContinue
$env:WP_ADMIN_PASSWORD = 'choose-a-long-unique-password'
.\setup.ps1
Remove-Item Env:WP_ADMIN_PASSWORD

On the first run, setup.ps1 creates a private .env with random database passwords. It starts only this Compose project, installs WordPress, activates the theme, sets Post name permalinks and the Manila timezone, and creates the four pages and seven menu dishes. Running it again preserves existing bookings and the admin password.

Open http://127.0.0.1:18087/. On a fresh installation, sign in at /wp-admin/ as site_admin with the password you chose. An existing installation keeps its original admin account. Open the captured email inbox at http://127.0.0.1:18088/.

If either default port is occupied, run .\setup.ps1 -SitePort 18089 -MailpitPort 18090 using free ports. On a fresh install you can also supply -AdminUser, -AdminEmail, and -SiteUrl.

3. Edit and operate the site

TaskWhere
Edit dishes, prices, categories, and imagesWordPress Admin → Menu dishes
View bookings and guest detailsWordPress Admin → Reservations
Release a booking slotMove that reservation to Trash
Review test emailsMailpit on local port 18088

Guest bookings accept parties of 1–8, dates up to 60 days ahead, and at least two hours' notice. A booking is complete when its reference appears on the confirmation page. A database lock enforces the current ten-party limit per 90-minute slot for simultaneous website requests. Set capacity to the real floor plan before launch.

4. Verify the installation

docker compose ps
node qa/reservation-smoke.mjs
node qa/capacity-smoke.mjs
python qa/chrome-mcp-check.py

The reservation test checks errors, booking confirmation, Mailpit delivery, and cleanup. The capacity test sends twelve simultaneous requests, accepts at most ten, and removes its test bookings. The Chrome MCP test checks navigation, menu filtering, mobile layout, and a browser booking. These checks need the local site running on the default ports.

To stop only this project, run docker compose down. Its database and WordPress volumes remain. Do not use down -v unless you intentionally want to erase its bookings and content.

Changing DB_PASSWORD in .env after a database already exists does not rotate its database user. Preserve the original value or perform an actual database password rotation. Keep .env, database backups, and guest records private.

6. Install on WordPress and verify a VPS

Live deployment is not yet verified. The tested Compose stack is local only: WordPress binds to localhost and email goes to Mailpit. Use a standard WordPress installation on the VPS, then complete the checks below before accepting real guest data.
  1. Install current WordPress with a supported PHP and database stack. Copy theme/ to wp-content/themes/salo/ or upload it as a theme ZIP; activate Restaurant Reservations. Set the homepage to Home, Post name permalinks, and the Asia/Manila timezone.
  2. Put WordPress behind a reverse proxy with a real domain and valid HTTPS certificate. Set WordPress Address and Site Address to the HTTPS domain; verify login, assets, and booking redirects.
  3. Install and configure a WordPress SMTP delivery plugin with the mail provider's authenticated settings. The theme sends through WordPress wp_mail(). Do not set RESTAURANT_DEMO_MAILPIT_HOST on the VPS. Send a plugin test email, then submit a real test booking and confirm delivery to both guest and administrator inboxes.
  4. Set the ten-party slot capacity to match the restaurant's actual tables. The database lock prevents simultaneous website submissions from exceeding that limit; staff must also respect it when entering bookings manually.
  5. Replace initial address, opening hours, dishes, prices, photos, and contact instructions. Add a privacy notice and a working cancellation/contact path.
  6. Add abuse protection to the public form, keep WordPress/themes/plugins patched, and use strong unique admin and database credentials. Back up the database and wp-content off the VPS, test restoration, and monitor site health and failed mail.

The local capacity and Mailpit tests passed. A live VPS, HTTPS, backup restore, and real SMTP delivery cannot be certified without the target server, domain, and mail-provider configuration. Do not publish the local .env or test admin credentials.
